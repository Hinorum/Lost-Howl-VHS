постепенно: `[ ]` → `[x]`. Пока есть хотя бы один unchecked `must-fix`,
переключать сеть **нельзя**.

## Must-fix (блокируют mainnet)

Без выполнения всех пунктов переключение TON_NETWORK=mainnet запрещено.
Падение любого из них = потеря денег или остановка игры без отката.

### Гонка при деплое
- [ ] Ретрай-перехват лока (`945867f`) задеплоен на Render.
      Мерж в `main` уже есть; пункт про код можно считать закрытым, но без
      деплоя Render rolling deploy по-прежнему оставит бот без tick'ов до
      ручного рестарта (реальный инцидент: 2026-10-01, 10:47 MSK, день не
      закрылся, лидерборд сентября не выплатился).

### Безопасность казны
- [ ] Создан отдельный **hot wallet** с балансом строго на 1–2 дня выплат.
- [ ] Основная казна вынесена на **cold wallet** (Ledger / Tonkeeper offline),
      ключ НЕ хранится на сервере.
- [ ] Написана процедура / скрипт пополнения hot с cold (ручной или
      с 2FA-подтверждением через отдельный канал).
- [ ] Доступ к Render-аккаунту только у доверенного лица, **2FA включена**.
- [ ] Мнемоника mainnet-кошелька НЕ появляется в логах (`grep -ri mnemonic logs/`
      даёт ноль вхождений реальных слов) и НЕ коммитится в репо (`grep -ri mnemonic`
      по исходникам не выдаёт значений 24 слов).
- [ ] В `app/handlers/admin.py` и `app/handlers/panel.py` проверен ручной
      «стоп-кран» (`/panel pause`, `/admin pause`): выплаты останавливаются
      за <5 секунд, ставки продолжают приниматься.

### Комиссии и экономика выплат
- [ ] `payout_fee_gram` пересчитан по реальным mainnet-комиссиям (5–10
      холостых переводов через Toncenter за выходные). Текущее `0.005`
      взято с testnet и на mainnet скорее всего неверно.
- [ ] `min_payout_gram` (сейчас `0.02`) и `referral_min_payout_gram`
      (сейчас `0.5`) пересмотрены: на mainnet это должны быть суммы, на
      которых комиссия не съедает больше 5–10% приза.
- [ ] Прогон `settle_week_if_due` и `settle_month_if_due` на testnet с
      реальными объёмами (копилка 50–100 TON) — нет ли «не хватает на
      последний приз» из-за округления комиссии.

### Подтверждение транзакций
- [ ] `payout.status='sent'` помечается только после N подтверждений
      в блокчейне (3–5 блоков ≈ 20–30 с), а не сразу после `bcast:` от
      лайтсервера. Альтернатива: отдельный статус `confirmed`,
      который ставится `confirm_broadcast_payouts` после сверки.
- [ ] Проверен сценарий «bcast: принято, но транзакция не в блоке за
      `payout_confirm_timeout_seconds = 7200`»: строка возвращается в
      `pending` и уходит заново, **без** двойного платежа (memo-антидубль).

### Холодный старт казначея
- [ ] Проверен cold start после 24-часового downtime: `get_seqno()` через
      лайтсерверы и через Toncenter v3 `runGetMethod` отдают одинаковый
      актуальный seqno, даже если за время простоя казначей получал
      внешние переводы.
- [ ] `get_wallet()` в `ton_pay/wallet.py` падает с понятной ошибкой,
      если производный адрес не совпал с настроенным (уже реализовано,
      но проверено на mainnet-паре).

## Should-fix (настоятельно рекомендуются)

Не блокируют mainnet, но без них эксплуатация = постоянные инциденты.

### HTTP-фолбэк на mainnet
- [ ] Холостой перевод 0.001 TON через `app/ton_pay/http_channel.py`
      прошёл успешно: BoC собран, `runGetMethod seqno` вернул число,
      `jsonRPC sendBoc` дал `ok: true`, через 15 с memo появилось в
      истории казначея.
- [ ] Сценарий «лайтсерверы мертвы (no alive peers)» обрабатывается
      чисто: переключение в HTTP-канал происходит за <30 с, алерт

### Мониторинг и алерты
- [ ] Алерт «pending-выплаты старше 10 минут» (через `ops.py:snapshot`
      или отдельный cron).
- [ ] Алерт «расхождение казначей ↔ БД > 1 TON»
      (на базе `app/treasury_mirror.py:diff`).
- [ ] Алерт «TonAPI деградировал» доходит до админа в Telegram
      (уже реализован в `app/ton_watch.py:1174`, проверить канал доставки).
- [ ] `/health` отдаёт `tick_failures`, `queue.pending`, `problems`
      как для testnet. На mainnet это должно мониториться отдельным
      watchdog'ом (UptimeRobot / Better Stack / собственным).

### Логирование и PII
- [ ] Маскирование `dest_address` в `logger.info` — последние 4 символа
      видны, остальное `…`. Полный адрес — только в `debug`.
- [ ] Маскирование `tx_hash` лидерборда в публичных сообщениях чата
      (это OK показывать, но в логах `info` уровня — не нужно).
- [ ] Retention логов: автоудаление через N дней (PII по `user_id` /
      `username` не должна копиться месяцами).

### Бэкапы
- [ ] `boot_maintenance` (`app/scheduler.py`) делает **реальный** pg_dump
      в шифрованный S3, а не «попытались и забили». Логи подтверждают.
- [ ] Восстановление из бэкапа отработано на тестовом Render-стенде.
- [ ] Ключ шифрования бэкапа НЕ на том же Render-аккаунте.

## Чек-лист перед переключением TON_NETWORK=mainnet

Финальная проверка в день X.

- [ ] Все пункты из секции **Must-fix** закрыты.
- [ ] Все пункты из секции **Should-fix** либо закрыты, либо явно
      отложены с описанием компенсирующих мер.
- [ ] На testnet проведена «финальная репетиция»: один полный цикл
      (ставка → закрытие дня → выплата приза + рейка → settle_week_if_due),
      все сообщения пришли в чаты и ЛС, лидерборд раздал призы, чаты
      получили посты.
- [ ] `TonAPI_KEY` оплачен / имеет нужный план для объёма mainnet
      (лимиты TonAPI: 1 rps на бесплатном, нужно проверить хватит ли).
- [ ] Stake_confirm_seconds=40 оставлен — это время подтверждения
      от TonAPI, а не блокчейн-финальность, запас разумный.
- [ ] `/panel` показывает корректный snapshot (`is_game_paused`,
      `last_tick_age_seconds`, `tick_fail_count`, `problems`).
- [ ] `payout.max_attempts` оставлен `5`, статусы
      `pending / sending / sent / failed / dismissed` с `CHECK`
      constraint в БД проверены миграцией.

## Процедура переключения

Когда чек-лист выше полностью зелёный:

1. **День X − 1**: зафиксировать активный день, дождаться его закрытия
   на testnet.
2. **День X, шаг 1**: установить переменные окружения на Render:
   - `TON_NETWORK=mainnet`
   - `TREASURY_ADDRESS=<hot wallet mainnet>`
   - `TREASURY_MNEMONIC=<24 слова hot wallet>`
   - `TON_API_KEY=<mainnet-ключ>`
   - `TREASURY_WALLET_VERSION=auto`
   - `LITESERVER_CONFIG_URL=https://ton.org/global.config.json`
   - `TONCENTER_API_BASE=https://toncenter.com`
3. **День X, шаг 2**: ручной рестарт Render-сервиса, чтобы `boot_game`
   сработал с новыми переменными (иначе `acquire_scheduler_lock` будет
   против старого инстанса).
4. **День X, шаг 3**: в логах убедиться, что появилось
   `INFO: Кошелёк казначея готов (mainnet, контракт v5r1)` (или v4r2 —
   что совпало по `detect_wallet_version`).
5. **День X, шаг 4**: провести «холостой» перевод 0.001 TON на собственный
   mainnet-кошелёк через `/admin payout test` (или аналог), убедиться,
   что memo появилось в истории казначея через 30–60 с.
6. **День X, шаг 5**: открыть новый день с минимальной ставкой
   (`stake_min_ton`), дождаться закрытия, убедиться, что выплата приза
   прошла в mainnet.
7. **День X, шаг 6**: перевести остаток с cold wallet на hot wallet,
   чтобы на ближайшие сутки было покрытие.
