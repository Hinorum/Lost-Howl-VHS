# LOST HOWL — сюжетное ядро: актуальный нарратив и промпты

Канон дизайна, актуализирован 2026-09/10 после запуска кассет
(`app/story/cassettes/tuman-na-viale.json` — сентябрь, `imeniny-chasov.json` — октябрь).
Обновление 2026-09/10-2 после разбора «Lost Dogs: The Way»: карты — три стратегии с
именами (care/dare/trick), эхо вчерашнего дня (`prev`), дневник ПОВ (`diary`),
сквозная дорога месяца.
Документ заменяет «вокзальный» слой `docs/story_world_manifest.md` и
`docs/story_cassette_design.md` в части рамки повествования: те остаются историей,
здесь — действующее.

**Честные поля (игровая поверхность дня):** пост дня несёт `chapter_text` и
`title`+`description` трёх карт; пост итогов — канон дня (`consequence` уцелевшей
карты), экономику и `diary`; эхо `prev` рендерится в начало главы следующего дня.
авторская дисциплина.

**Рамка одной строкой:** бот целиком = видеомагнитофон **LOST HOWL**, собранный из хлама.
У него нет своего мира и своей стаи. Раз в месяц кто-то (хранитель) ставит в лоток кассету —
фанфик-продолжение по миру «Lost Dogs: The Way» (стая псов ищет дом в разрушенном городе).
Плеер проигрывает плёнку, игроки голосуют **один из трёх черновиков кадра**, и по закону дня
(большинство / меньшинство / середина) движок решает, какой кадр «уцелел». Уцелевший черновик
пишет **канон дня** — он звучит в итогах и остаётся памятью месяца. Остальные два черновика
уходят в архив: они больше **не всплывают ни в следующих сценах, ни в следующих кассетах**.

**То, что промпты не могут менять (жёсткая рамка):**
- Голосование ровно 3 варианта (`position 0/1/2`). Закон дня и его энтропию считает движок
  `app/rounds/…` из TON-энтропии (`root_hash % 3`) — кассета пишет только режиссёрскую метку

- Одна кассета = ровно один календарный месяц (28–31 день, день = день месяца). Вне своего
  месяца кассета молчит: движок живёт шаблоном (fail-open), кривая кассета не роняет игру.
- Следующую кассету на месяц выбирает хранитель в `/panel` (`STORY_CASSETTE_NEXT_KEY`).
- Дистрибуция $Gram (пул дня = 100% − рейк, по умолчанию 95% / лидерборды / Фонд Стаи /
  хранитель / рефераль), очки, лидерборды — вне сюжетного слоя. Сюжет их не упоминает,
  не обещает, не отыгрывает.
- Ветвление сюжета — только через «перемотку» (см. §2), максимум `MAX_FORKS` (4) переключателя
  на месяц. Никакого дерева 31×3.
- Невыбранные черновики не «отзываются» в будущем: ни шрамов на плёнке, ни эхо. Память несёт
  только уцелевшее (канон дня). Каждая кассета — самостоятельная история: крючков между
  месяцами нет, продолжать предыдущую кассету не обязательно (см. §2).

## 1. Контракт кассеты (зеркало `app/story/schema.py` — поддерживать 1:1)

```
Cassette:
  cassette_id: str            # имя плёнки
  month: "YYYY-MM"            # ровно месяц по календарю
  title: str
  logline: str | None
  attribution: str | None     # ≤ 200, клеймо плёнки: «фанатская плёнка по мотивам …»
  switch: list[Fork]          # 0–4 перемотки; по умолчанию — без ветвлений
  days: list[Day]             # главная дорога (main): день месяца, day_index 1..N подряд

Day:
  day_index: int              # день месяца
  station: str                # место сцены (кадр); движок её не читает, но внутри одной
                              # дороги станция должна быть уникальна — это ритм месяца
  chapter_title: str          # ≤ 80, показывается в посте целиком (заголовок — реклама, не роман)
  chapter_text: str           # ≤ 700 — сцена (голос плёнки), показывается в посте дня ЦЕЛИКОМ;
                              # рекомендация: 250–450 знаков = 1–2 экрана телефона
                              # читает и не перситирует (см. §2): уровень драмы держи
                              # в первой фразе chapter_text, а не здесь
  cards: [Card]               # ровно 3, position 0/1/2 без дублей
                              # поле оставлено для совместимости, не пиши
  prev: {int: str} | None     # ≤ 3 ключей (0/1/2) · каждое значение ≤ 160 —
                              # «эхо вчерашнего»: как стая вспомнит канон, если вчера
                              # победила карта N. Рендерится в начале главы следующего дня.
                              # Это ответ на «когда следующий день знает предыдущий»:
                              # знает ровно в момент рендера дня N по закрытому кадру дня N−1.
  diary: str | None           # ≤ 200 — запись дневника (детский/обыденный ПОВ-контраст к
                              # эпической главе); звучит в итогах дня после канона (см. §2).

Fork (перемотка, SwitchModel):
  to: str                     # имя дороги, ≤ 32
  at_day: int                 # ≥ 2: первый день дороги `to`
  winner: 0|1|2               # чья карта уцелела в день at_day-1, чтобы включить дорогу
  days: list[Day]             # день месяца от at_day до N подряд (это и есть дорога `to`)

Card:
  position: 0|1|2
  title: str            # ≤ 80 — имя пути как ПОСТУПОК/СТРАТEГИЯ («Вскрыть крышу»,
                        # «Подвальный ход»), а не «Путь I/II/III»
  description: str      # ≤ 260 — суть развилки, показывается в посте дня (витрина до ставки)
  consequence: str      # ≤ 220 — канон дня: звучит в итогах, ТОЛЬКО если эта карта уцелела;
                        # у проигравших не печатается и в сценарий не возвращается
  tag: "care"           # авторская метка характера; движок tag не читает (метки
                        # сцен всегда «care») — держи 3 стратегии care/dare/trick
                        # как самопроверку баланса, не как обязательство движку
  image_path: ""        # необязательно
```

**Три карты дня — три РАВНОПРАВНЫХ голоса/стратегии** (жёсткое требование, перенесено из
канона «The Way»): каждая карта — отдельный характер пути (осторожный/дерзкий/хитрый),
имя = поступок, а не «плохой/хороший». Все три — честные кандидаты: развилка пишется
так, что её может решить ЛЮБОЙ закон дня (большинство/меньшинство/середина) — автор не
знает, какой закон выпадет движку (энтропия TON), поэтому в тексте главы нет ни слова
про то, «как решат»: это делает движок и пост.

**Эхо и дневник — локальная память месяца** (см. §2): `prev` связывает день с его
собственным вчера внутри одной плёнки, `diary` даёт эмоциональный контраст в итогах.
Оба опциональны: без них кассета валидна, движок играет как раньше (fail-open).

**Бюджет режиссуры:** по месяцу ожидается ≈ N/3 дней на каждый из трёх законов, толеранс ±2
(нарушение = warning, не ошибка). Бюджет считается по **главной дороге (main)**; дни `any`
бюджет не тратят — держи их не больше N/3−8 (при N=30 — не больше 2), а в перемотках
сохраняй те же ≈N/3, иначе дорога получит перекос.

**Стоп-слова (эвристика по подстроке в нижнем регистре, совпадение = кассета отвергнута):**
`woof`, `notcoin`, `$not`, `$bones`, `binance`, `bybit`, `okx`, `airdrop`, `токен`, `инвестици`,
`доход`, `заработ`, `прибыль`, `памп`, `криптобирж`, `сиквел`, `официальн`. Названия мира
Lost Dogs (Догтаун, мутагены, имена персонажей) — **разрешены**: это открытый неофициальный
фанфик. Но **дословных заимствований** фраз и сцен оригинальной игры не делаем: герои
месяца — свои, канонные персонажи оригинала не становятся героями плёнки.

## 2. Ветвление «перемотка» и память месяца

- Кассета несёт **главную дорогу** `days` и 0–4 **перемотки** (`switch`).
  Плёнка обычно идёт по `main`; дороги сходятся к финалу месяца (сходимость —
  авторское пожелание: валидатор проверяет целостность дорог, не сходимость).
- Перемотка `{winner, to, at_day}`: **если движок объявил победителем дня
  `at_day − 1` карту `winner` (0/1/2), то, начиная со следующего дня и до конца
  месяца, играется дорога `to`** (её дни — поле `days` перемотки, day_index = at_day..N).
  Решение честное и только по уже закрытому кадру: победителя кассета
  спрашивает у движка (winner_card раунда по дате opens_at), сам не выдумывает.
- Несколько перемоток каскадятся по датам: учитывается последняя, сработавшая
  на текущий день. Перемотки независимы — каждая смотрит только на победителя
  движка в свой день решения.
- Реализация без правки движка: активная дорога вычисляется в `app/story/bay.py`
  при рендере дня из базы (уже закрытые раунды). Сбоя нет / победителя нет /
  раунда нет → играем `main` (fail-open). `WatcherState` движок не трогает.
- **Память месяца** — это уцелевшее: канон дня (`consequence` уцелевшей карты) печатается в
  итогах и кладётся в `StoryBeat` (winning_title / winning_text / counts). Крючков между
  Каждая кассета — самостоятельная история: продолжать сюжет предыдущей можно по желанию
  автора, но это не правило и его отсутствие — не брак.
  Невыбранные варианты не попадают ни в канон, ни в память и больше нигде не появляются.
- **Эхо вчерашнего (`prev`)** — как следующий день «знает» предыдущий: при рендере дня N
  проигрыватель читает честного победителя дня N−1 (winner_card движка по дате opens_at)
  и подставляет его эхо в начало главы дня N. Это НЕ развилка: ``switch`` разводит дороги,
  а `prev` связывает их между собой текстом. Дня-вчера нет / эха под победителя нет /
  сбой — глава рендерится без эха (fail-open).
- **Дневник (`diary`)** — запись ПОВ (ребёнок/обыденный голос) в итогах дня: читается
  проигрывателем из активной кассеты по дате и дню закрытого раунда, печатается в посте
  итогов после канона и экономики. Нет поля/кассеты — строки нет, сухие итоги не зависят
  от сюжета (fail-open).

## 3. Промпт А — «Сюжетное ядро» (контракт; сверено с реализацией)

> Роль: сюжетное ядро — модуль `app/story/` (схема-контракт + проигрыватель бай), который
> принимает кассеты и крутит их по месяцу, — **не трогая игровой движок**.
>
> **Жёсткая рамка (не меняем):**
> - Голосование ровно 3 варианта (`position 0/1/2`). Закон дня (majority/minority/median) и
>   его энтропию считает движок `app/rounds/…` из TON: ядро подставляет главу и три карты
>   поверх честного payload движка (точка встройки — `_plan_and_render` в `app/story/bay.py`,
>   подключение — `install_bay` в `app/main.py`).
> - Одна кассета = один календарный месяц, `day_index = день месяца`, кассета активна только
>   когда `month` файла == текущему месяцу. Вне месяца и при кривой кассете — fail-open:
>   движок играет шаблоном, игра и стейки не падают.
> - Следующую кассету месяца выбирает хранитель в `/panel` (`STORY_CASSETTE_NEXT_KEY`);
>   при перекрытии нескольких кассет одного месяца побеждает выбранная, иначе первая по
>   алфавиту.
> - Дистрибуция $Gram, лидерборды, Фонд, рефералка — вне сюжетного слоя.
> - Ветвление — только «перемотка»: контракт `switch` из §2. Не более `MAX_FORKS` (4) switch
>   на месяц; все дороги сходятся к финалу.
>
> **Контракт кассеты** — ровно как в §1 (поля, лимиты, 3 карты с position 0/1/2, бюджет

>
> **Как работает (эталон реализации):**
> - Дорога дня не хранится отдельно: `bay._resolution` читает победителей движка (`winner_card`
>   закрытых раундов по дате opens_at) из БД и применяет перемотки при рендере дня.
> - День из кассеты: `cassette.day_for(today.day, road)`; подменяются только `chapter_title`,
>   `chapter_text` и `cards` поверх честного payload (`rule`/`rule_entropy` приходят от движка).
> - Сбой расчёта дороги, отсутствие кассеты или её месяца → движок-шаблон (fail-open).
> - Победитель дня и его канон: движок закрывает раунд своим «Путь N»; канон дня — текст
>   `consequence` уцелевшей карты, печатается в итогах и сохраняется в `StoryBeat`
>   (winning_title / winning_text / counts). Крючков между кассетами нет; невыбранные карты
>   не персистятся движком вовсе.
>
> **Логи и служебные сообщения ядра** — голос LOST HOWL (плёнка, перемотка, PLAY), без шума
> в стейке и без обещаний.
>
> **Критерий приёмки:** движок не изменился, кроме двух аддитивных точек — однажды
> вызываемого `install_bay` в `app/main.py` и заполнения канона дня в
> `app/rounds/narrative.py::write_epilogue` (уцелевший `consequence` попадает в итоги через
> `epilogue_text`); месяц играется от кассеты; ни кривая кассета, ни отсутствие
> кассеты не валят стейки, очки и лидерборды; тесты: валидация дней=календарь, табу, бюджет,
> fail-open, выбор кассеты через /panel, перемотка (победитель → новая дорога → схождение),
> канон дней — только победивший `consequence`.

## 4. Промпт Б — «Сюжетная кассета» (актуальный нарратив, автор месяца-фанфика)

> Роль: автор кассеты для плеера **LOST HOWL**. Ты фанат, расстроенный тем, что авторы
> «Lost Dogs: The Way» молчат больше полугода, и пишешь неофициальное продолжение вручную —
> одну плёнку на месяц. В ней стая псов с характерами ищет дом в разрушенном городе,
> каждую сцену стая решает голосованием: **один из трёх черновиков кадра уцелеет, напишет
> канон дня и останется памятью месяца; остальные два уходят в архив — они больше не
> всплывают ни в следующих сценах месяца, ни в следующих кассетах**.
>
> **Вход:** месяц «YYYY-MM» (число дней N посчитай по календарю), номер кассеты в серии,
> образцы уже вышедших плёнок (`app/story/cassettes/*.json`). Серия — не обязательство:
> **каждая кассета — самостоятельная история**, продолжать сюжет и детали предыдущего месяца
> не требуется (это выбор автора, а не правило).
>
> **Формат вывода:** JSON-файл кассеты строго по контракту §1 (`app/story/schema.py`).
> Прогони файл через валидатор — `validate_file` из `app/story/schema.py` — и добейся `ok`
> (warnings допустимы только по привязке эха prev и стилю).
>
> **Ритм месяца (не план, разметка).** Для N дней расставь границы (для N=30 — как ниже,
>   для других N — по долям):
> - **Зачин, дни 1..≈N/φ²** (для 30 — до 11). Мир до того, как месяц начался. Первые 3 дня —
>   «входные билеты»: кто такая стая, что за штуки в месяце, кто в этой плёнке говорит.
>   Ни одного необратимого решения до середины месяца.
> - **Середина, день ≈N/φ** (для 30 — 18–19). Поворот: открытие, меняющее **статус** героя
>   (узнали, назвали, записали, выгнали). До него герой жил в своём углу — после стал чьим-то
>   следом.
> - **Накал, дни 20..N−4.** Две-три точки накала: дни, где ставка выше обычной (уходящий свет,
>   сломанный довод, публичный долг, чужой свидетель).
> - **Кульминация, дни N−3..N−2.** Ровно ОДИН день, в котором месяц решается: три карты — не
>   оттенки настроения, а три разные судьбы месяца.
> - **Развязка, последние 2–3 дня.** Расплата и новое равновесие. Новых вопросов и крючков на
>   следующую кассету нет.
> - **Единая цена месяца.** Выбери ОДНУ потерю/отказ/уход и заплати её в кульминации: чужой
>   след, сломанное обещание, дом, который месяц держали. Месяц без цены — брак: «все
>   довольны» развязкой не считается.
> - **Этический день: минимум один в первой и один во второй половине** — день, где ни одна
>   карта не «правильная»: все три стоят чужого (совести, слова, доверия).
> - **Сквозной мотив с выплатой.** Один предмет/запах/слово месяца: заведи в первой половине
>   (предвосхищение: герой его не понимает), удиви в середине, **выплати в развязке** — чтобы
>   последние дни читались ответом первому дню.
>
> **Жёсткие правила:**
> - Дней в файле = N календарных, `day_index` подряд 1..N. Каждый день — одна сцена: глава +
>   ровно 3 карты. Карты — три **сюжетно равноправных** черновика одного поворота (не «плохой/
>   средний/хороший», а три разных по смыслу хода). Все три должны быть честными кандидатами:
>   каждый может уцелеть по закону дня.
> - **Три карты = три стратегии-характера** (канон «The Way»): каждый путь — поступок с
>   именем («Крыша-козырь», «Подвальный ход»), а не номер. Держи три голоса:
>   `care` (сберечь/выждать), `dare` (рискнуть/напасть), `trick` (хитрить/обмануть).
>   Ни один не должен выглядеть «плохим» — каждый ведёт стаю по-своему.
> - **Стратегии обязаны менять места.** Пост всегда печатает «I.», «II.», «III.» и кнопки
>   «Сцена I/II/III» — это движок. Если `care` всегда сидит на II, а `trick` на III, игрок за
>   три дня выучит расклад и перестанет выбирать. Норма: каждая стратегия садится в каждую
>   позицию не меньше N/12 раз (при N=30 — 2–3 раза) и не живёт в одной позиции три дня
>   подряд. Имя карты — поступок; номер добавит движок, повторять его в имени не надо.
> - **Драматическая нейтральность закона — во всех полях.** Ты не знаешь, какой закон дня
>   выпадет движку (энтропия TON), поэтому **ни одно поле** — `chapter_text`, `description`,
>   `consequence`, `prev`, `diary` — не говорит, как решат: табу «закон», «большинство»,
>   «меньшинство», «середина», «решат», «выберут», «голосуют», «счёт», «ставка». Закон дня —
>   событие поста, а не текст. Развилка должна читаться драматично при ЛЮБОМ законе: выбирают
>   поступки, а не правило. `consequence` пишется **как свершившееся** («Стая вывела стаю к
>   ручью»), без сослагательности и без отчёта о процессе («выбрали…», «решили…»).
> - `consequence` — **канон дня, только если именно эта карта уцелела**: он печатается в
>   итогах после экономики и сохраняется в память месяца (`StoryBeat.winning_text`). У
>   проигравших `consequence` не печатается и не отзывается в следующих сценах — не
>   закладывай «последствия проигрыша» в последующие дни и не повторяй фразы невыбранных карт.
> - **Эхо (`prev`)** — следующий день помнит вчерашний выбор; это главный текст месяца, канон
>   доходит до игрока и через итоги, и через эхо завтрашнего дня. Для дня N дай эхо для ВСЕХ
>   трёх карт дня N−1 (до 3 ключей, каждое ≤ 160, минимум 2 из 3, в сильных точках — все 3).
>   **`prev` — последствие, а НЕ пересказ канона**: опиши, что ИЗМЕНИЛОСЬ вследствие выбора
>   (сместился запах, ушёл след, появилась метка), не повторяя текст `consequence`. Эхо вправе
>   говорить только о прошлом — никаких обещаний сегодняшнего исхода. Первый день — без эха
>   (норма). **На первом дне перемотки пиши только ключ, равный `winner` этой перемотки** —
>   эхо рендерится только под честного победителя дня `at_day−1`, остальные два ключа не
>   покажутся никогда.
> - **Дневник (`diary`)**: запись обыденного ПОВ (щенок, пёс-сторож, старик), контраст к
>   эпической главе (≤ 200). Звучит в итогах после канона и экономики (как дневник Беллы в
>   «The Way»). 4–8 записей на месяц, в сильных точках (после поворота, перед кульминацией,
>   в развязке), **не подряд** — минимум 3 дня между записями.
> - `chapter_text` — сама сцена, её показывают в посте дня целиком (≤ 700, рекомендация
>   250–450 знаков: один кадр, который стая видит до выбора, не роман). Это текст
>   дня, а не крючок для следующего месяца: месяцы не обязаны продолжать друг друга.
>   её не читает и не перситирует; уровень драмы держи в первой фразе `chapter_text`, а не здесь.
>   Серийность кассет — только по желанию автора, её отсутствие — не брак.

>   хода), minority — Меньшинство (скрытого/рискованного), median — Середина (компромисса).
>   По месяцу ≈ N/3 на каждый (±2), **бюджет считается по главной дороге (main)**; дни `any`
>   бюджет не тратят — держи их не больше N/3−8 (при N=30 — не больше 2), а в перемотках
>   сохраняй те же ≈N/3, иначе дорога получит перекос.
> - **Путь-рама всего месяца**: месяц тянет одну сквозную дорогу (к дому/к цели/из тьмы),
>   у неё видна дальность — «до дома осталось столько-то дневных переходов». Стая проходит
>   её главами, и эпическое «число пути» (день/остаток) читается в титулах, а не в цифрах
>   игроков: **никаких чисел комьюнити, банков, ставок и обещаний дохода в тексте** (это за
>   сюжетным слоем — стоп-слова §1).
> - **Сквозной мотив с выплатой** — то, что держит месяц: один предмет/запах/слово, заведён
>   в первой половине (предвосхищение: герой его не понимает), удивляет в середине и
>   **выплачивается в развязке** (последние дни читаются ответом первому дню).
> - **Персонажи как голоса** (канон «The Way»): 3–5 голосов стаи со своими речевыми
>   привычками (проповедник, ворчун-инженер, щенок-летописец, хитрец-жонглёр); у каждого
>   ≥ 2 появлений за месяц, один — в точке накала; «комический» голос можно вести фоном и
>   вернуть в сильной точке. Они узнаются по фразам, а не по аватарам; прозвище-архетип
>   годно и предпочтительнее поголовья имён. Канон Догтауна разрешён (фанфик).
> - Тон — тёплый быт апокалипсиса: циничный юмор, характеры, «все псы хорошие, но разными
>   путями». Не хоррор, не слезливая драма; смерть/тоска — только если она растит стаю в
>   пределах месячной арки.
> - Канон дозволен (Догтаун, мутагены, архетипы вожаков), потому что это откровенный
>   фанфик: ставь клеймо `attribution` («Фанатская плёнка по мотивам Lost Dogs: The Way.
>   Не канон.») — его отсутствие только warning, но по-фанатски всегда проставляется.
>   Но **дословных заимствований** фраз и сцен оригинала не делаем: герои месяца — свои,
>   канонные персонажи оригинала не становятся героями плёнки.
>   **Запрещено:** токены, биржи, airdrop, доход/заработок, слово «официальн»
>   (стоп-слова §1).
> - **Перемотка — честная арифметика.** В день `at_day−1` у месяца ровно три исхода:
>   `winner=0` играет main, `winner=1` — дорога A, `winner=2` — дорога B. Отсюда правила:
>   - **не больше 2 перемоток на один `at_day`** (карт всего три) и у них **разные `winner`**;
>     дубль пары (`at_day`, `winner`) — брак: вторая дорога в `road()` молча теряется, её дни
>     никогда не отыграются;
>   - **`main` обязан быть внятным третьим исходом**: дни `at_day..N` главной дороги пишутся
>     полностью, даже если кажется, что «winner=0 не случится»;
>   - **карта дня `at_day−1` в позиции, равной `winner`**, читается как вход в эту дорогу
>     (интрига названия, последняя строка описания);
>   - **бюджет объёма**: всех объектов дня (main + дороги) не больше **1.5N**. При N=30 и
>     `at_day=28` две перемотки стоят 6 лишних дней; при `at_day=20` — уже 22, месяц
>     раздувается. Ставь `at_day` в последнюю треть (N−10…N−3);
>   - **на первом дне дороги в `prev` пиши только ключ, равный `winner` этой перемотки**;
>   - **сходимость дорог**: последние 2–3 дня на всех дорогах — один вопрос месяца; дороги
>     расходятся только в ответе, не в предмете.
>   Целостность дорог (≤4, без дублей, дни at_day..N, разные `winner`) проверяет валидатор.
>   Без ветвлений тоже можно — месяц тогда держится одной дорогой и общей аркой.
> - **Станция — ритм места**: `station` не повторяется внутри дороги; последняя треть месяца —
>   три разных места, а не «комната/плёнка/динамик» подряд. Смена места — дешёвый способ
>   дать месяцу ритм; не трать его на повторы.
> - Голос LOST HOWL — в меру, только в сильных точках (старт/конец, поворот): «ПЛЕЙ»,
>   потрескивание, шум пустой плёнки на стыке дней. Не ломиться в каждый абзац.
>
> **Самопроверка перед сдачей:** (1) дней = N; (2) 3 карты по контракту, все три — честные
> кандидаты и три разные стратегии (care/dare/trick); (3) стратегии ротируют позиции — ни одна
> не сидит в одной позиции три дня подряд и в каждой позиции ≥ N/12; (4) привязка эха prev
> ≈ N/3 по главной дороге, `any` не больше N/3−8; (5) месяц целен, самостоятелен, тянет одну
> сквозную дорогу со сквозным мотивом и единой ценой; (6) станции не повторяются внутри
> дороги, последняя треть — три разных места; (7) перемотки по арифметике: ≤2 на `at_day`,
> разные `winner`, объём ≤ 1.5N, `at_day` в последней трети, на первом дне дороги `prev`
> только у ключа `winner`; (8) стоп-слов нет, цифр комьюнити/банка нет; (9) ритм месяца:
> зачин/поворот/накал/одна кульминация/развязка; (10) весь месяц держит один logline и
> 3–5 голосов с ≥2 появлениями, один — в накале; (11) файл проходит `validate_file` с `ok`;
> (12) ни один текст невыбранного черновика не повторяется в последующих сценах месяца;
> (13) эхо `prev` — последствие, а не пересказ канона, и не предсказывает победителя;
> (14) дневник (`diary`) в сильных точках, не подряд (минимум 3 дня между записями);
> (15) антипаттерны: ≤1 «как будто/будто» на день, ≤2 «впервые» на месяц, имена карт внутри
> дороги не дублируются.

## 5. Минимальная встройка (что менять в коде и почему эти изменения — последние)

1. `app/story/schema.py` — контракт кассеты (§1), лимиты, табу, валидация дней =
   календарь; `switch` (перемотки): не более `MAX_FORKS` (4) за месяц, дороги не
   дублируются, дни дороги идут at_day..N подряд, `winner` в 0..2; мягкое
   замечание при отсутствии `attribution`. Методы `road(today_day, winners)`
   и `day_for(today_day, road)` — выбор дня по дороге.
2. `app/story/bay.py` — при рендере дня: активная дорога по победителям движка
   (winner_card раунда по дате opens_at, из БД), день по дороге через
   `cassette.day_for`. Сбой/нет победителя → главная дорога (fail-open).
   **Эхо вчерашнего:** `_prev_echo(session, today, day)` — победитель дня N−1 →
   подстановка строки `prev[winner]` в начало главы дня N (fail-open при
   отсутствии кадра/эха). **Дневник итогов:** `day_diary(session, finished)` —
   запись `diary` из активной кассеты по дате и дню закрытого раунда, печатается
   в `broadcast.results_body` после экономики (fail-open).
   Подключение — `install_bay` в `app/main.py`; движок и жизненный цикл раундов
   не меняются — правок вне `app/story/` нет.
3. Тексты бота (профиль «Плеер LOST HOWL», /start, /help, /menu-пульт, пост дня:
   глава + три пути) — голос LOST HOWL (косметика). Канон в итогах — текст
   `consequence` уцелевшей карты; рядом — запись дневника `diary` (если есть).
   Пост дня: эхо вчерашнего (`prev`) приходит в главе автоматически из `bay`.
4. `app/story/cassettes/*.json` — кассеты-фанфики по промпту Б (образцы:
   `tuman-na-viale.json` 2026-09, `imeniny-chasov.json` 2026-10).

Блокчейн-механики, стейки, очки, лидерборды, редистрибуция $Gram — **не изменяются вообще**.

## 6. Редактор кассет: как хранитель вносит правки (инструкция)

Кассета в репозитории — JSON-эталон (`app/story/cassettes/*.json`). Хранитель правит
не JSON, а **YAML-сценарий**: декомпилятор отдаёт его файлом, компилятор собирает
правку обратно через тот же `validate_payload`, что движок. Контракт не дублируется:
единственный гейт — `app/story/schema.py`. Общее ядро — `app/story/editor.py`,
его используют и CLI `scripts/cassette_tool.py`, и панель бота (не расходятся).

Правка всегда файлом: скачал YAML → изменил в любом текстовом редакторе → вернул
документом. Кривой файл кассету не трогает: бот/CLI сначала валидируют, пишут
только после `ok`, битое отвечают ошибками без записи.

### Через Telegram (`/cassette` — самый простой путь)

1. `/cassette` — список библиотеки; у каждой плёнки кнопка **🎞** → «Редактор плёнки».
2. **Контекст плёнки** под шапкой редактора: 🟢 если назначена «следующей», ▶ если
   играется (месяц совпадает с текущим) — «сегодня день N · дорога X» (честное
   решение движка, fail-open в main).
3. **Прочитать / скачать:** «Скачать месяц (.yaml)» — весь месяц YAML-документом;
   «Скачать день» → сетка дней (сверху кнопки дорог: main и перемотки) → кнопка с
   номером N — фрагмент дня одним YAML-файлом; «Прочитать день» → номер N — кадр
   текстом в чат.
4. **Вернуть месяц/день:** «📤 Вернуть …» — бот встаёт в режим «жду документ»; пришли
   скачанный `.yaml` (исправленный) — отчёт «✅ Сценарий принят: …» или «❌ …» с полями
   ошибок. Дорогу дня бот узнаёт из метки фрагмента `# дорога: …`: день 20 на
   перемотке morning встанет в `switch`, а не в main. Отмену — «⏹ Отменить загрузку».
5. **Проверить без записи:** «🔎 Проверить месяц/день» — валидация файла (сумма дней,
   форма, контракт), файл кассеты не трогается; отчёт «✅ … Проверено — файл не
   изменён». Удобно перед штатной правкой, чтобы поймать опечатку YAML.
6. **Новая кассета:** «➕ Новый месяц» — пришли сценарий нового месяца документом
   (образец возьми «Скачать месяц» любой плёнки). Имя выводится из `cassette_id`
   и месяца (`мел-2026-02.json`); существующие плёнки перезаписывать нельзя.
7. **Undo:** каждая запись правки делает бэкап `*.json.bak`; восстановить предыдущий
   вариант — «🗄 Вернуть бэкап» (кнопка в сцене и в отчёте правки). Бэкап перед
   копией валидируется, битый не трогает рабочую кассету.
8. Намерение «жду документ» живёт в `watcher_state` (`STORY_CASSETTE_EDIT_KEY`),
   держится до приёма документа или отмены — зависнуть нельзя.

Документы читаются как текст (UTF-8, с BOM терпимо). После записи проигрыватель
`bay.py` перечитывает файл по mtime на ближайшем рендере.

### Из терминала (CLI — тот же редактор, без Telegram)

```
.\.venv\Scripts\python scripts\cassette_tool.py dump app\story\cassettes\imeniny-chasov.json
                              # месяц целиком: пишет imeniny-chasov.yaml рядом с json (или -o сценарий.yaml)
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14 --road morning
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 12 -o edits/day12.yaml
                              # фрагмент дня (с меткой # дорога: …)
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits/day12.yaml --check
                              # дорога и день читаются из фрагмента, флаги не нужны
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits/day12.yaml --day 12 --road morning
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\imeniny-chasov.yaml --check
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\imeniny-chasov.yaml   # на место
```

`--check` — валидация без записи. `--day`/`--road` — явный override: по умолчанию
день и дорога читаются из самого фрагмента (day_index и `# дорога: …`); `--day` ещё
и сверяет заявленное с фрагментом (страховка от ручной правки).

### Что можно и что нельзя

- Можно: правки глав/текста/вариантов внутри месяца, дорог перемотки (фрагмент
  с `--road morning`), титула, logline; эха `prev` и дневника `diary` (видны в
  «Прочитать день» как строки «(эхо…)»/«(дневник стаи)»); новую кассету («➕ Новый
  месяц» — имя из cassette_id+месяца); откат правки («🗄 Вернуть бэкап»). Ограничение
  «3 карты, position 0/1/2, день = календарю» — то же, что у автора (§1):
  недееспособную правку не примет ни бот, ни CLI.
- Нельзя из бота/CLI: переименовать существующий файл, менять число дней месяца,
  дистрибуцию, законы дня — это за движком (§3).
- Тесты вокруг редактора: `tests/test_cassette_editor.py` (ядро + панель),
  `tests/test_cassette_tool.py` (CLI round-trip).
