# LOST HOWL — кассеты: контракт, генерация, редактор

Источник истины — код: `app/story/schema.py` (контракт, лимиты, валидатор),
`app/story/narrative_lint.py` (повествовательные проверки), `app/story/bay.py`
(проигрыватель), `app/story/editor.py` и `scripts/cassette_tool.py` (правки).
При расхождении этого документа с кодом верен код.

**Рамка проигрывателя.**
- Бот проигрывает календарный месяц как плёнку видеомагнитофона LOST HOWL:
  хранитель кладёт в лоток кассету — фанфик по миру «Lost Dogs: The Way».
  Кассета написана заранее: все дни месяца уже лежат в её файле.
- Голосование дня — ровно 3 варианта (`position` 0/1/2). Какой черновик кадра
  уцелел, решает закон дня движка из энтропии мастерчейна TON
  (`root_hash % 3`, `app/rounds/rendering.py`); кассета на закон не влияет
  и в текстах его не называет.
- Уцелевший черновик — канон дня: хранится в `StoryBeat` и в пост игрокам
  не печатается. Два проигравших не всплывают никогда: ни в следующих сценах,
  ни в следующих кассетах.
- Одна кассета = ровно один календарный месяц: `day_index` = день месяца,
  дней ровно по календарю (28–31). Месяц кассеты не совпал с текущим —
  кассета не играет, движок живёт шаблоном (`fail-open`); битый файл игру
  не роняет по этой же причине.
- Если кассет одного месяца в библиотеке несколько — какую играть, решает
  хранитель в `/panel` (`STORY_CASSETTE_NEXT_KEY`); без выбора берётся первая
  по алфавиту имени файла.
- Ветвление месяца — только перемотки `switch` (≤ `MAX_FORKS` = 4), и только
  по уже закрытому кадру (см. §2).
- Дистрибуция $Gram (ставки: 96% — угадавшим путь, 1% — Фонд Стаи, 2% —
  недельная копилка, 0,5% — хранителю, 0,5% — месячная копилка; при
  реферальных ставках победителям 95% — `app/config.py`), очки и лидерборды —
  вне сюжетного слоя: кассета их не упоминает и не обещает.
- Кассеты не связаны между собой: каждая — самостоятельная история,
  продолжаться предыдущей она не обязана.

**Честные поля (игровая поверхность дня).** Пост дня: эхо вчерашнего выбора
(`prev` в начале главы) → сюжет (`chapter_text`) → блок «что предстоит решить»
(`dilemma`) → три кнопки голосования (подпись — `title` карты, без
последствий). Пост итогов — сухие итоги и экономика дня, без сюжета. Дневник
`diary` уходит отдельной рассылкой в 17:00 UTC (джоба `story-diary`). Поля
`card.description` нет. Поля `logline` в контракте нет: лишние ключи JSON
валидатор игнорирует, редактор при записи не сохраняет.

## 1. Контракт кассеты (зеркало `app/story/schema.py`)

```
Cassette:
  cassette_id: str
  month: "YYYY-MM"            # ровно календарный месяц
  title: str
  attribution: str | None     # ≤ 200 — клеймо плёнки
  switch: list[Fork]          # 0–4 перемотки; по умолчанию []
  days: list[Day]             # главная дорога (main): day_index 1..N подряд

Day:
  day_index: int              # день месяца
  station: str                # место кадра; в пост не идёт
  chapter_title: str          # ≤ 80 — заголовок поста, показывается целиком
  chapter_text: str           # ≤ 700 (рекомендация 250–450) — сцена дня,
                              # показывается целиком
  dilemma: str                # ≤ 400, обязательна — блок «что предстоит решить»
  cards: [Card]               # ровно 3, позиции 0/1/2 без дублей
  prev: {0|1|2: str} | None   # значение ≤ 160 — эхо вчерашнего выбора;
                              # рендерится в начало главы следующего дня
  diary: str | None           # ≤ 200 — запись дневника; отдельная рассылка

Fork (SwitchModel):
  to: str                     # имя дороги, ≤ 32; не дублируется
  at_day: int                 # ≥ 2 и ≤ N: первый день дороги
  winner: 0|1|2               # победитель дня at_day − 1, включающий дорогу
  days: list[Day]             # day_index ровно at_day..N подряд

Card:
  position: 0|1|2
  title: str                  # ≤ 80 — имя пути-поступка; идёт в кнопку
                              # голосования (кнопка режет значения > 64
                              # знаков по словам)
  consequence: str            # ≤ 220 — канон, ТОЛЬКО если карта уцелеет;
                              # в пост не печатается
  tag: "care" | "dare" | "trick"  # метка стратегии: в игре не используется,
                              # её читает narrative_lint
```

Лимиты равны показу: `chapter_title` 80, `dilemma` 400 и `consequence` 220
схема не выпускает длиннее, чем показывает пост; глава дня жёстко ≤ 700
(рендер страхует легаси-раунды клампом 1500).

**Три карты дня — три равноправных стратегии:** `care` (сберечь), `dare`
(рискнуть), `trick` (хитрить). Имя карты — поступок («Вскрыть крышу»,
«Подвальный ход»), не «Путь I/II/III» и не «плохой/хороший». Все три —
честные кандидаты: развилка пишется так, что её решает любой закон дня,
какой выпадет движку.

**Стоп-слова** (эвристика по подстроке в нижнем регистре; совпадение —
кассета отвергнута): `woof`, `notcoin`, `$not`, `$bones`, `binance`, `bybit`,
`okx`, `airdrop`, `токен`, `инвестици`, `доход`, `заработ`, `прибыль`, `памп`,
`криптобирж`, `сиквел`, `официальн`. Названия мира Lost Dogs (Догтаун,
мутагены, имена персонажей) разрешены — это открытый фанфик; но дословных
заимствований фраз и сцен оригинальной игры нет, канонные персонажи оригинала
героями плёнки не становятся.

**Валидатор:** жёстко — структура, лимиты, позиции карт, календарь, дубли
дорог и пар (at_day, winner), стоп-слова; мягко (warning) — мёртвые ключи
`prev` на первом дне дороги перемотки, `prev`, пересказывающий свой день
вместо вчерашнего, глава короче 140 знаков одним предложением или длиннее
600 знаков, пустая `attribution`.

## 2. Ветвление «перемотка» и память месяца

- Главная дорога `days` + 0–4 перемотки `switch`. Перемотка `{winner, to,
  at_day}`: если в день `at_day − 1` уцелела карта `winner`, то с дня `at_day`
  до конца месяца играется дорога `to` (её `days`: `day_index` = at_day..N).
- Победителя кассета берёт у движка из базы (winner_card раунда по дате
  opens_at). Победителя нет / раунда нет / сбой расчёта — играется `main`
  (`fail-open`).
- Сработавшие перемотки каскадятся по датам: активная дорога дня — последняя
  сработавшая (`Cassette.road`).
- **Память месяца** — только уцелевшее: `consequence` победившей карты →
  `StoryBeat` (`winning_title` / `winning_text` / counts). Проигравшие не
  сохраняются нигде.
- **Эхо (`prev`):** при рендере дня N `bay._prev_echo` читает победителя дня
  N−1 и подставляет `prev[winner]` в начало главы. День 1 — без эха. Первый
  день дороги перемотки помнит только фиксированного `winner`; другие ключи
  там мертвы (warning).
- **Дневник (`diary`):** `bay.day_diary` читает запись активной кассеты по
  дате и дню открытого дня; уходит отдельной рассылкой в 17:00 UTC (джоба
  `story-diary`, `broadcast.announce_day_diary`). Нет поля — рассылки нет.
- Реализация — патч `bay.install_bay` (`_plan_and_render`); движок раундов
  и `WatcherState` не меняются.

## 3. Промпт Б — генерация кассеты (инструкция автору)

### Вход / выход

**Вход:** месяц `YYYY-MM` (N дней по календарю).
**Выход:** JSON-файл по контракту §1 в `app/story/cassettes/`.
**Гейты:** `schema.validate_file` — без ошибок;
`scripts/cassette_tool.py lint <кассета>.json --strict` — без замечаний.

---

### Ритм месяца (разметка по долям N)

| Фаза | Дни (N=30) | Что происходит |
|---|---|---|
| Зачин | 1..≈N/φ² (1–11) | Мир до месяца. Первые 3 дня — входные билеты: кто стая, что за мир, кто говорит. Ни одного необратимого решения до середины. |
| Поворот | ≈N/φ (18–19) | Открытие, меняющее **статус** героя (узнали, назвали, записали, выгнали). |
| Накал | 20..N−4 | 2–3 точки: ставка выше обычного (уходящий свет, сломанный долг, чужой свидетель). |
| Кульминация | N−3..N−2 | Один день, где месяц решается. Три карты — три разные судьбы, не оттенки настроения. |
| Развязка | N−2..N | Расплата, новое равновесие. Без новых крючков. |

**Обязательные элементы ритма:**
- **Единая цена месяца** — одна потеря/отказ/уход, выплаченная в кульминации.
- **Этический день** — минимум 1 в каждой половине: ни одна карта не «правильная».
- **Сквозной мотив** — один предмет/запах/слово: завести в первой половине, удивить в середине, выплатить в развязке.
- **Путь-рама** — одна сквозная дорога (к дому/к цели/из тьмы) с видимой дальностью. Чисел комьюнити/банка/ставок в тексте нет.

---

### Карты (3 штуки, позиции 0/1/2)

- `care` (сберечь) / `dare` (рискнуть) / `trick` (хитрить) — все три честные,
  уцелеть может каждая.
- Имя карты = поступок («Вскрыть крышу», «Подвальный ход»).
- **Ротация позиций:** каждая стратегия в каждой позиции ≥ N/12 раз и не
  три дня подряд в одной позиции (проверяет `narrative_lint`).
- `title` ≤ 80 (кнопка режет значения > 64 знаков по словам). `consequence`
  ≤ 220, пишется как свершившееся («Стая вывела к ручью»), без
  «выбрали/решили».
- `consequence` уцелевшей карты = канон дня (в `StoryBeat`, в пост не идёт).
  Проигравшие не сохраняются.

---

### Текст дня (поля)

| Поле | Лимит | Что писать |
|---|---|---|
| `station` | — | Место сцены. Не повторяется внутри дороги. Последняя треть — 3 разных места. |
| `chapter_title` | ≤ 80 | Заголовок поста. Уровень драмы — в первой фразе `chapter_text`, не здесь. |
| `chapter_text` | ≤ 700 (рекомендация 250–450) | Сцена целиком в пост. Один кадр, не роман. Без крючков для следующего месяца. |
| `dilemma` | ≤ 400 | Обязательно. 1–3 предложения: напряжение дня (чего стая не может избежать). Не список вариантов, не обещание последствий. Форма — вопрос или острое утверждение. |

**Пост дня:** эхо → сюжет → дилемма → кнопки.

---

### Эхо (`prev`)

- Для дня N дай эхо для карт дня N−1. Ключ = позиция: `prev[p]` — эхо
  вчерашнего `consequence[p]`.
- Минимум 2 из 3 ключей; в сильных точках — все 3. Каждое ≤ 160.
- **Последствие, а не пересказ:** что изменилось (сместился запах, ушёл след,
  появилась метка). Без цепочек ≥ 4 слов подряд из вчерашнего `consequence`.
- Только о прошлом. Без обещаний сегодняшнего исхода.
- День 1 — без эха. На первом дне дороги перемотки — только ключ = `winner`
  этой перемотки.

---

### Дневник (`diary`)

- Запись обыденного ПОВ (щенок, пёс-сторож, старик). ≤ 200. Контраст
  к эпической главе.
- 4–8 записей на месяц, в сильных точках (после поворота, перед
  кульминацией, в развязке).
- Не подряд — минимум 3 дня между записями.

---

### Перемотки (`switch`)

- 0–4 перемотки. `at_day` в последней трети (N−10..N−3). Объём всех дорог
  ≤ 1.5N.
- Не больше 2 перемоток на один `at_day`, с разными `winner`.
- `main` = третий исход: дни `at_day..N` главной дороги пишутся полностью.
- Карта дня `at_day − 1` в позиции `winner` = вход в дорогу.
- Последние 2–3 дня на всех дорогах — один вопрос месяца; дороги расходятся
  в ответе, не в предмете.
- Без ветвлений тоже можно.

---

### Закон дня — не упоминать

Автор не знает закон дня и не может его спланировать. В любом текстовом поле
(`chapter_text`, `dilemma`, `consequence`, `prev`, `diary`) не должно быть
слов: закон · большинство · меньшинство · середина · решат · выберут ·
голосуют · счёт · ставка. Развилка должна читаться драматично при любом
законе. Стоп-слова §1 проверяет валидатор; этот список — редакционное
требование.

---

### Персонажи, тон, канон

- **3–5 голосов** стаи с речевыми привычками (проповедник, ворчун, щенок,
  жонглёр). У каждого ≥ 2 появлений, одно — в точке накала.
  Прозвище-архетип предпочтительнее поголовья имён.
- **Тон:** тёплый быт апокалипсиса, циничный юмор. Не хоррор, не слезливая
  драма.
- Ставь `attribution`: «Фанатская плёнка по мотивам Lost Dogs: The Way.
  Не канон.» Канон Догтауна разрешён (фанфик); дословных заимствований
  фраз/сцен оригинала нет; герои месяца — свои.
- **Голос LOST HOWL** — в меру, только в сильных точках («ПЛЕЙ»,
  потрескивание, шум плёнки).

---

### Самопроверка

1. Дней = N, `day_index` подряд 1..N.
2. 3 карты, все — честные кандидаты, теги care/dare/trick ротируют позиции
   (≥ N/12, без стриков ≥ 3).
3. `prev` со 2-го дня: ≥ 2 из 3 ключей, последствие ≠ пересказ, без обещаний.
4. `dilemma` у каждого дня: проблема без вариантов и без повтора слов главы.
5. `diary` 4–8 записей, пропуски ≥ 3 дней.
6. Станции не повторяются; последняя треть — 3 разных места.
7. Перемотки: ≤ 2 на `at_day`, разные `winner`, `at_day` в N−10..N−3,
   объём ≤ 1.5N.
8. Стоп-слов нет. Чисел комьюнити/банка нет. Закон дня не назван.
9. Ритм: зачин → поворот → накал → кульминация → развязка. Единая цена
   в кульминации.
10. Сквозной мотив заведён → удивлён → выплачен. 3–5 голосов, у каждого
    ≥ 2 появлений.
11. ≤ 1 «как будто/будто» на день. ≤ 2 «впервые» на месяц. Имена карт
    не дублируются.
12. `validate_file` — без ошибок; `cassette_tool.py lint --strict` — чисто.

## 4. Встройка (карта кода)

1. `app/story/schema.py` — контракт §1, лимиты, стоп-слова, календарь,
   перемотки (≤ `MAX_FORKS`, уникальные дороги и пары (at_day, winner), дни
   at_day..N), методы `road(today_day, winners)` и `day_for(today_day, road)`.
2. `app/story/bay.py` — активная кассета месяца и активная дорога при рендере
   дня (победители — из базы по opens_at); эхо `_prev_echo`; дневник
   `day_diary`; выбор «следующей» (`STORY_CASSETTE_NEXT_KEY`); кэш библиотеки
   по mtime. Сбой в любом месте → `main` / шаблон (`fail-open`).
3. `app/story/narrative_lint.py` — повествовательные проверки: ротация тегов,
   дубли станций и имён карт, эхо-пересказ, штампы. Клиенты — CLI `lint`
   и панель `/cassette`; замечания не гейт (`--strict` валит прогон).
4. Тексты бота (профиль «Плеер LOST HOWL», /start, /help, /menu, пост дня:
   эхо + глава + дилемма + кнопки) — голос LOST HOWL (косметика). Итоги дня —
   сухой блок; канон в пост не идёт; дневник — отдельным постом в 17:00 UTC.
5. `app/story/editor.py` + `scripts/cassette_tool.py` — правки кассет
   YAML-сценарием (§5); библиотека — `app/story/cassettes/*.json`
   (или `STORY_CASSETTES_DIR`).

Блокчейн-механики, стейки, очки, лидерборды, дистрибуция $Gram — не меняются.

## 5. Редактор кассет (инструкция хранителю)

Кассета в репозитории — JSON-эталон (`app/story/cassettes/*.json`). Хранитель
правит не JSON, а YAML-сценарий: декомпилятор отдаёт его файлом, компилятор
собирает правку обратно через тот же `validate_payload`, что движок.
Единственный гейт — `app/story/schema.py`; общее ядро — `app/story/editor.py`
(его используют и CLI `scripts/cassette_tool.py`, и панель бота).

Правка всегда файлом: скачал YAML → изменил в текстовом редакторе → вернул
документом. Битый файл кассету не трогает: сначала валидация, запись — только
после `ok`.

### Через Telegram (`/cassette`)

1. `/cassette` — список библиотеки; у каждой плёнки кнопка **🎞** → «Редактор
   плёнки».
2. Контекст плёнки под шапкой: 🟢 назначена «следующей»; ▶ играется —
   «сегодня день N · дорога X».
3. Прочитать / скачать: «📥 Скачать месяц (.yaml)» — весь месяц одним YAML;
   «📥 Скачать день» → сетка (кнопки дорог: main и перемотки) → номер дня —
   фрагмент дня одним YAML-файлом; «📄 Прочитать день» → номер дня — кадр
   текстом в чат.
4. Вернуть месяц/день: «📤 Вернуть …» — бот ждёт документ; пришли скачанный
   `.yaml` (исправленный) — отчёт «✅ …» или «❌ …» с полями ошибок. Дорогу
   дня бот узнаёт из метки фрагмента `# дорога: …`. Отмена — «⏹ Отменить
   загрузку».
5. Проверка без записи: «🔎 Проверить месяц» / «🔎 Проверить день» — валидация
   файла, кассета не трогается; отчёт «✅ … Проверено — файл не изменён».
6. Новая кассета: «➕ Новый месяц» — пришли сценарий нового месяца документом.
   Имя выводится из `cassette_id` и месяца (slug-месяц.json); существующие
   плёнки не перезаписываются.
7. Undo: перед каждой записью бот делает бэкап `*.json.bak`; «🗄 Вернуть
   бэкап» восстанавливает предыдущий вариант. «💾 Снять бэкап» — ручной слепок
   без правки (прежний `.bak` перезаписывается). Битый бэкап рабочую кассету
   не трогает.
8. Намерение «жду документ» живёт в `watcher_state`
   (`STORY_CASSETTE_EDIT_KEY`) до приёма документа или отмены.

Документы читаются как текст (UTF-8, BOM терпимо). После записи проигрыватель
перечитывает изменённые файлы по mtime на ближайшем рендере.

### Из терминала (CLI — тот же редактор)

```
.\.venv\Scripts\python scripts\cassette_tool.py dump app\story\cassettes\<кассета>.json
                              # месяц целиком: пишет <кассета>.yaml рядом с json (или -o сценарий.yaml)
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14 --road <дорога>
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 12 -o edits\day12.yaml
                              # фрагмент дня (с меткой # дорога: …)
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits\day12.yaml --check
                              # дорога и день читаются из фрагмента, флаги не нужны
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits\day12.yaml --day 12 --road <дорога>
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\<сценарий>.yaml --check
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\<сценарий>.yaml   # на место
.\.venv\Scripts\python scripts\cassette_tool.py lint app\story\cassettes\<кассета>.json --strict
```

`--check` — валидация без записи. `--day`/`--road` в `patch` — явный override:
по умолчанию день и дорога читаются из самого фрагмента (`day_index` и
`# дорога: …`); `--day` сверяет заявленное с фрагментом. `lint --strict` —
код возврата 1 при любом замечании.

### Что можно и что нельзя

- Можно: правки глав/текста/вариантов внутри месяца; дорог перемотки
  (фрагмент с `--road`); титула; эха `prev` и дневника `diary` (видны
  в «Прочитать день»); новую кассету («➕ Новый месяц»); откат правки
  («🗄 Вернуть бэкап»).
- Нельзя из бота/CLI: переименовать существующий файл, менять число дней
  месяца, дистрибуцию, законы дня — это за движком.
- Тесты редактора: `tests/test_cassette_editor.py` (ядро + панель),
  `tests/test_cassette_tool.py` (CLI round-trip).
