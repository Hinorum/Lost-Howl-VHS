# LOST HOWL — сюжетное ядро: актуальный нарратив и промпты

Канон дизайна, актуализирован 2026-10 после ревизии октябрьской кассеты под этот
стандарт (`imeniny-chasov.json`): narrative_lint 35 → 0, все 90 эхо переписаны под
позиционный контракт, стоп-слова и штампы вычищены. Образцы: `tuman-na-viale.json` —
сентябрь 2026, `imeniny-chasov.json` — октябрь 2026, `lost-howl-krysina-tropa-2026-11.json`
и `lost-howl-svet-v-tupike-2026-11.json` — ноябрь 2026.
Обновление 2026-09/10-2 после разбора «Lost Dogs: The Way»: карты — три стратегии с
именами (care/dare/trick), эхо вчерашнего дня (`prev`), дневник ПОВ (`diary`),
сквозная дорога месяца.
Актуализация 2026-10-11: эпилог из механики снесён (канон дня — только `StoryBeat`,
в пост итогов не идёт), дневник `diary` — отдельная рассылка в 17:00 UTC, из
общего блока итогов убраны римские цифры.
Промпт А (написание сюжетного ядра) выполнен и удалён:
действующее — контракт §1, ветвление §2, авторский Промпт Б §3, встройка §4,
редактор §5.

**Честные поля (игровая поверхность дня):** у дня одна структура поста — эхо
вчерашнего выбора (`prev` в начале главы) → сюжет (`chapter_text`) → блок
«что предстоит решить» (`dilemma`). Три варианта живут только в кнопках под
постом (их подписи — `title` карт, без последствий): витрины вариантов в тексте
дня нет (поля `card.description` больше нет). Пост итогов — сухие итоги и экономика
дня, без сюжета: канон хранится в `StoryBeat` и в пост не идёт, дневник `diary`
уходит отдельной рассылкой в 17:00 UTC; эхо `prev` рендерится в начало главы
следующего дня.

**Рамка одной строкой:** бот целиком = видеомагнитофон **LOST HOWL**, собранный из хлама.
У него нет своего мира и своей стаи. Раз в месяц кто-то (хранитель) ставит в лоток кассету —
фанфик-продолжение по миру «Lost Dogs: The Way» (стая псов ищет дом в разрушенном городе).
Плеер проигрывает плёнку, игроки голосуют **один из трёх черновиков кадра**, и по закону дня
(большинство / меньшинство / середина) движок решает, какой кадр «уцелел». Уцелевший черновик
пишет **канон дня** — он остаётся памятью месяца (в пост игрокам не идёт). Остальные два черновика
уходят в архив: они больше **не всплывают ни в следующих сценах, ни в следующих кассетах**.

**То, что промпты не могут менять (жёсткая рамка):**
- Голосование ровно 3 варианта (`position 0/1/2`). Закон дня и его энтропию считает движок
  `app/rounds/…` из TON-энтропии (`root_hash % 3`); кассета закон не называет в текстах
  и не может его сдвинуть — в её авторской власти только три черновика кадра.
- Одна кассета = ровно один календарный месяц (28–31 день, день = день месяца). Вне своего
  месяца кассета молчит: движок живёт шаблоном (fail-open), кривая кассета не роняет игру.
- Следующую кассету на месяц выбирает хранитель в `/panel` (`STORY_CASSETTE_NEXT_KEY`).
- Дистрибуция $Gram (пул дня = 100% − рейк, по умолчанию 95% / лидерборды / Фонд Стаи /
  хранитель / рефераль), очки, лидерборды — вне сюжетного слоя. Сюжет их не упоминает,
  не обещает, не отыгрывает.
- Ветвление сюжета — только через «перемотку» (см. §2), максимум `MAX_FORKS` (4) переключателя
  на месяц. Никакого дерева 31×3.
- Невыбранные черновики не «отзываются» в будущем: ни шрамов на плёнке, ни эхо. Память несёт
  только уцелевшее (канон дня). Каждая кассета — самостоятельная история: крючков между
  месяцами нет, продолжать предыдущую кассету не обязательно (см. §2).

## 1. Контракт кассеты (зеркало `app/story/schema.py` — поддерживать 1:1)

```
Cassette:
  cassette_id: str            # имя плёнки
  month: "YYYY-MM"            # ровно месяц по календарю
  title: str
  logline: str | None
  attribution: str | None     # ≤ 200, клеймо плёнки: «фанатская плёнка по мотивам …»
  switch: list[Fork]          # 0–4 перемотки; по умолчанию — без ветвлений
  days: list[Day]             # главная дорога (main): день месяца, day_index 1..N подряд

Day:
  day_index: int              # день месяца
  station: str                # место сцены (кадр) — в пост не идёт, но линт требует
                              # уникальности внутри дороги: это ритм месяца
  chapter_title: str          # ≤ 80, показывается в посте целиком (заголовок — реклама:
                              # его не читают и не персистируют — уровень драмы держи
                              # в первой фразе chapter_text, а не здесь)
  chapter_text: str           # ≤ 700 — сцена (голос плёнки), показывается в посте дня ЦЕЛИКОМ;
                              # рекомендация: 250–450 знаков = 1–2 экрана телефона
  dilemma: str                # ≤ 400, ОБЯЗАТЕЛЬНО — блок «что предстоит решить»:
                              # проблема/дилемма/вопрос дня, звучит в посте после
                              # сюжета и замыкает повествование перед кнопками.
                              # Назови НАПРЯЖЕНИЕ дня (чего стая не может избежать),
                              # но не перечисляй варианты и не обещай последствий —
                              # это делают кнопки (title) и канон (consequence).
                              # Не повторяй фразы chapter_text и prev (линт ловит).
  cards: [Card]               # ровно 3, position 0/1/2 без дублей
                              # title карт идёт в кнопки голосования: лимит схемы 80,
                              # а сама кнопка показывает ≈64 и длиннее обрезает по словам
  prev: {int: str} | None     # ≤ 3 ключей (0/1/2) · каждое значение ≤ 160 —
                              # «эхо вчерашнего»: как стая вспомнит канон, если вчера
                              # победила карта N. Рендерится в начале главы следующего дня.
                              # Это ответ на «когда следующий день знает предыдущий»:
                              # знает ровно в момент рендера дня N по закрытому кадру дня N−1.
  diary: str | None           # ≤ 200 — запись дневника (детский/обыденный ПОВ-контраст к
                              # эпической главе); уходит отдельной рассылкой в 17:00 UTC (см. §2).

Fork (перемотка, SwitchModel):
  to: str                     # имя дороги, ≤ 32
  at_day: int                 # ≥ 2: первый день дороги `to`
  winner: 0|1|2               # чья карта уцелела в день at_day-1, чтобы включить дорогу
  days: list[Day]             # день месяца от at_day до N подряд (это и есть дорога `to`)

Card:
  position: 0|1|2
  title: str            # ≤ 80 — имя пути как ПОСТУПОК/СТРАТEГИЯ («Вскрыть крышу»,
                        # «Подвальный ход»), а не «Путь I/II/III»
  consequence: str      # ≤ 220 — канон дня: память месяца (StoryBeat.winning_text),
                        # ТОЛЬКО если эта карта уцелела; в пост не печатается,
                        # у проигравших не возвращается в сценарий
  tag: "care"|"dare"|"trick"  # авторская метка характера; в игре не используется
                        # (движок фолбэчится на «care»), но её читает narrative_lint:
                        # по ней проверяется ротация позиций care/dare/trick
```

**Три карты дня — три РАВНОПРАВНЫХ голоса/стратегии** (жёсткое требование, перенесено из
канона «The Way»): каждая карта — отдельный характер пути (осторожный/дерзкий/хитрый),
имя = поступок, а не «плохой/хороший». Все три — честные кандидаты: развилка пишется
так, что её может решить ЛЮБОЙ закон дня (большинство/меньшинство/середина) — автор не
знает, какой закон выпадет движку (энтропия TON), поэтому в тексте главы нет ни слова
про то, «как решат»: это делает движок и пост.

**Эхо и дневник — локальная память месяца** (см. §2): `prev` связывает день с его
собственным вчера внутри одной плёнки, `diary` даёт эмоциональный контраст отдельным
постом в 17:00 UTC. Оба опциональны: без них кассета валидна, движок играет как раньше (fail-open).

**Стоп-слова (эвристика по подстроке в нижнем регистре, совпадение = кассета отвергнута):**
`woof`, `notcoin`, `$not`, `$bones`, `binance`, `bybit`, `okx`, `airdrop`, `токен`, `инвестици`,
`доход`, `заработ`, `прибыль`, `памп`, `криптобирж`, `сиквел`, `официальн`. Названия мира
Lost Dogs (Догтаун, мутагены, имена персонажей) — **разрешены**: это открытый неофициальный
фанфик. Но **дословных заимствований** фраз и сцен оригинальной игры не делаем: герои
месяца — свои, канонные персонажи оригинала не становятся героями плёнки.

## 2. Ветвление «перемотка» и память месяца

- Кассета несёт **главную дорогу** `days` и 0–4 **перемотки** (`switch`).
  Плёнка обычно идёт по `main`; дороги сходятся к финалу месяца (сходимость —
  авторское пожелание: валидатор проверяет целостность дорог, не сходимость).
- Перемотка `{winner, to, at_day}`: **если движок объявил победителем дня
  `at_day − 1` карту `winner` (0/1/2), то, начиная со следующего дня и до конца
  месяца, играется дорога `to`** (её дни — поле `days` перемотки, day_index = at_day..N).
  Решение честное и только по уже закрытому кадру: победителя кассета
  спрашивает у движка (winner_card раунда по дате opens_at), сам не выдумывает.
- Несколько перемоток каскадятся по датам: учитывается последняя, сработавшая
  на текущий день. Перемотки независимы — каждая смотрит только на победителя
  движка в свой день решения.
- Реализация без правки движка: активная дорога вычисляется в `app/story/bay.py`
  при рендере дня из базы (уже закрытые раунды). Сбоя нет / победителя нет /
  раунда нет → играем `main` (fail-open). `WatcherState` движок не трогает.
- **Память месяца** — это уцелевшее: канон дня (`consequence` уцелевшей карты) кладётся в
  `StoryBeat` (winning_title / winning_text / counts) и в пост игрокам не идёт. Крючков между
  месяцами нет: каждая кассета — самостоятельная история, продолжать сюжет предыдущей
  можно по желанию автора, но это не правило и его отсутствие — не брак.
  Невыбранные варианты не попадают ни в канон, ни в память и больше нигде не появляются.
- **Эхо вчерашнего (`prev`)** — как следующий день «знает» предыдущий: при рендере дня N
  проигрыватель читает честного победителя дня N−1 (winner_card движка по дате opens_at)
  и подставляет его эхо в начало главы дня N. Это НЕ развилка: ``switch`` разводит дороги,
  а `prev` связывает их между собой текстом. Дня-вчера нет / эха под победителя нет /
  сбой — глава рендерится без эха (fail-open).
- **Дневник (`diary`)** — запись ПОВ (ребёнок/обыденный голос): читается
  проигрывателем из активной кассеты по дате и дню открытого дня и уходит отдельной
  рассылкой в 17:00 UTC (из поста итогов снят — указ владельца). Нет поля/кассеты —
  рассылки нет, сухие итоги не зависят от сюжета (fail-open).

## 3. Промпт Б — генерация кассеты (инструкция автору)

### Вход / выход

**Вход:** месяц `YYYY-MM` (N дней по календарю), образцы кассет (`app/story/cassettes/*.json`).
Каждая кассета — самостоятельная история; продолжать предыдущую не обязательно.

**Выход:** JSON-файл строго по контракту §1. Прогони через `validate_file` — добейся `ok` при
warnings 0.

---

### Ритм месяца (разметка по долям N)

| Фаза | Дни (N=30) | Что происходит |
|---|---|---|
| Зачин | 1..≈N/φ² (1–11) | Мир до месяца. Первые 3 дня — входные билеты: кто стая, что за мир, кто говорит. Ни одного необратимого решения до середины. |
| Поворот | ≈N/φ (18–19) | Открытие, меняющее **статус** героя (узнали, назвали, записали, выгнали). |
| Накал | 20..N−4 | 2–3 точки: ставка выше обычного (уходящий свет, сломанный долг, чужой свидетель). |
| Кульминация | N−3..N−2 | Один день, где месяц решается. Три карты — три разные судьбы, не оттенки настроения. |
| Развязка | N−2..N | Расплата, новое равновесие. Без новых крючков. |

**Обязательные элементы ритма:**
- **Единая цена месяца** — одна потеря/отказ/уход, выплаченная в кульминации. Месяц без цены — брак.
- **Этический день** — минимум 1 в каждой половине: ни одна карта не «правильная».
- **Сквозной мотив** — один предмет/запах/слово: завести в первой половине, удивить в середине, выплатить в развязке.
- **Путь-рама** — одна сквозная дорога (к дому/к цели/из тьмы) с видимой дальностью. Никаких чисел комьюнити/банка/ставок в тексте.

---

### Карты (3 штуки, позиции 0/1/2)

- Три **равноправных** стратегии: `care` (сберечь), `dare` (рискнуть), `trick` (хитрить).
  Все три — честные кандидаты, каждый может уцелеть.
- Имя карты = поступок («Вскрыть крышу», «Подвальный ход»), не «Путь I/II/III».
- **Ротация позиций:** каждая стратегия в каждой позиции ≥ N/12 раз и не 3 дня подряд в одной позиции. (Проверяет `narrative_lint`.)
- `title` ≤ 80 (кнопка показывает ~64). `consequence` ≤ 220, пишется **как свершившееся** («Стая вывела к ручью»), без «выбрали/решили».
- `consequence` уцелевшей карты = канон дня (хранится в `StoryBeat`, в пост не идёт). Проигравшие не сохраняются и не отзываются в будущем.

---

### Текст дня (поля)

| Поле | Лимит | Что писать |
|---|---|---|
| `station` | — | Место сцены. Не повторяется внутри дороги. Последняя треть — 3 разных места. |
| `chapter_title` | ≤ 80 | Реклама. Уровень драмы — в первой фразе `chapter_text`, не в заголовке. |
| `chapter_text` | ≤ 700 (рекомендация 250–450) | Сцена целиком в пост. Один кадр, не роман. Без крючков для следующего месяца. |
| `dilemma` | ≤ 400 | Обязательно. 1–3 предложения: напряжение дня (чего стая не может избежать). НЕ список вариантов, НЕ обещание последствий. Форма — вопрос или острое утверждение. |

**Пост дня:** эхо → сюжет → дилемма → кнопки.

---

### Эхо (`prev`)

- Для дня N дай эхо для карт дня N−1. Ключ = позиция: `prev[p]` — эхо **вчерашнего** `consequence[p]`.
- Минимум 2 из 3 ключей; в сильных точках — все 3. Каждое ≤ 160.
- **Последствие, а не пересказ:** опиши, что ИЗМЕНИЛОСЬ (сместился запах, ушёл след, появилась метка). Без цепочек ≥4 слов подряд из вчерашнего `consequence`.
- Только о прошлом. Без обещаний сегодняшнего исхода.
- День 1 — без эха. На первом дне перемотки — только ключ = `winner` этой перемотки.

---

### Дневник (`diary`)

- Запись обыденного ПОВ (щенок, пёс-сторож, старик). ≤ 200. Контраст к эпической главе.
- 4–8 записей на месяц, в сильных точках (после поворота, перед кульминацией, в развязке).
- Не подряд — минимум 3 дня между записями.

---

### Перемотки (`switch`)

- 0–4 перемотки. `at_day` в последней трети (N−10..N−3). Объём всех дорог ≤ 1.5N.
- Не больше 2 перемоток на один `at_day`, с разными `winner`.
- `main` = третий исход: дни `at_day..N` главной дороги пишутся полностью.
- Карта дня `at_day−1` в позиции `winner` = вход в дорогу (интрига названия).
- Последние 2–3 дня на всех дорогах — один вопрос месяца; дороги расходятся в ответе, не в предмете.
- Без ветвлений тоже можно.

---

### Закон дня — табу во всех полях

Движок выбирает закон по энтропии TON (большинство/меньшинство/середина). Автор его не знает
и не может спланировать. В **любом** текстовом поле (`chapter_text`, `dilemma`, `consequence`,
`prev`, `diary`) запрещены слова:

> закон · большинство · меньшинство · середина · решат · выберут · голосуют · счёт · ставка

Развилка должна читаться драматично при ЛЮБОМ законе. Стоп-слова §1 (`airdrop`, `токен`,
`доход` и т.д.) — кассета отвергнута валидатором.

---

### Персонажи, тон, канон

- **3–5 голосов** стаи с речевыми привычками (проповедник, ворчун, щенок, жонглёр). У каждого ≥ 2 появлений, одно — в точке накала. Прозвище-архетип предпочтительнее поголовья имён.
- **Тон:** тёплый быт апокалипсиса, циничный юмор. Не хоррор, не слезливая драма.
- **Канон Догтауна разрешён** (фанфик). Ставь `attribution`: «Фанатская плёнка по мотивам Lost Dogs: The Way. Не канон.» Дословных заимствований фраз/сцен оригинала — нет; герои месяца — свои.
- **Голос LOST HOWL** — в меру, только в сильных точках («ПЛЕЙ», потрескивание, шум плёнки).

---

### Самопроверка

1. Дней = N, `day_index` подряд 1..N.
2. 3 карты, все — честные кандидаты, теги care/dare/trick ротируют позиции (≥ N/12, без стриков ≥3).
3. `prev` со 2-го дня: ≥ 2 из 3 ключей, последствие ≠ пересказ, без обещаний.
4. `dilemma` у каждого дня: проблема без вариантов и без повтора слов главы.
5. `diary` 4–8 записей, пропуски ≥ 3 дней.
6. Станции не повторяются; последняя треть — 3 разных места.
7. Перемотки: ≤2 на `at_day`, разные `winner`, `at_day` в N−10..N−3, объём ≤ 1.5N.
8. Стоп-слов нет. Чисел комьюнити/банка нет. Закон дня не назван.
9. Ритм: зачин → поворот → накал → кульминация → развязка. Единая цена в кульминации.
10. Сквозной мотив заведён → удивлен → выплачен. 3–5 голосов, у каждого ≥ 2 появлений.
11. ≤ 1 «как будто/будто» на день. ≤ 2 «впервые» на месяц. Имена карт не дублируются.
12. `validate_file` → `ok`, warnings 0.

## 4. Встройка (карта кода: где что живёт)

1. `app/story/schema.py` — контракт кассеты (§1), лимиты, табу, валидация дней =
   календарь; `switch` (перемотки): не более `MAX_FORKS` (4) за месяц, дороги не
   дублируются, дни дороги идут at_day..N подряд, `winner` в 0..2; мягкое
   замечание при отсутствии `attribution`. Методы `road(today_day, winners)`
   и `day_for(today_day, road)` — выбор дня по дороге.
2. `app/story/bay.py` — при рендере дня: активная дорога по победителям движка
   (winner_card раунда по дате opens_at, из БД), день по дороге через
   `cassette.day_for`. Сбой/нет победителя → главная дорога (fail-open).
   **Эхо вчерашнего:** `_prev_echo(session, today, day)` — победитель дня N−1 →
   подстановка строки `prev[winner]` в начало главы дня N (fail-open при
   отсутствии кадра/эха). **Дневник дня:** `day_diary(session, round_row)` —
   запись `diary` из активной кассеты по дате и дню переданного (открытого) дня;
   уходит отдельной рассылкой в 17:00 UTC (`broadcast.day_diary_message` →
   `announce_day_diary`, джоба `story-diary`, fail-open).
   Подключение — `install_bay` в `app/main.py`; движок и жизненный цикл раундов
   не меняются — правок вне `app/story/` нет.
3. Тексты бота (профиль «Плеер LOST HOWL», /start, /help, /menu-пульт, пост дня:
   эхо + глава + блок дилеммы, три сцены — кнопками под постом) — голос
   LOST HOWL (косметика). Итоги дня — сухой блок с экономикой: канон в пост
   не идёт (живёт в `StoryBeat`), дневник `diary` — отдельным постом в 17:00 UTC.
   Пост дня: эхо вчерашнего (`prev`) приходит в главе автоматически из `bay`.
4. `app/story/cassettes/*.json` — кассеты-фанфики по промпту Б (образцы:
   `tuman-na-viale.json` 2026-09, `imeniny-chasov.json` 2026-10,
   `lost-howl-krysina-tropa-2026-11.json`, `lost-howl-svet-v-tupike-2026-11.json` — 2026-11).

Блокчейн-механики, стейки, очки, лидерборды, редистрибуция $Gram — **не изменяются вообще**.

## 5. Редактор кассет: как хранитель вносит правки (инструкция)

Кассета в репозитории — JSON-эталон (`app/story/cassettes/*.json`). Хранитель правит
не JSON, а **YAML-сценарий**: декомпилятор отдаёт его файлом, компилятор собирает
правку обратно через тот же `validate_payload`, что движок. Контракт не дублируется:
единственный гейт — `app/story/schema.py`. Общее ядро — `app/story/editor.py`,
его используют и CLI `scripts/cassette_tool.py`, и панель бота (не расходятся).

Правка всегда файлом: скачал YAML → изменил в любом текстовом редакторе → вернул
документом. Кривой файл кассету не трогает: бот/CLI сначала валидируют, пишут
только после `ok`, битое отвечают ошибками без записи.

### Через Telegram (`/cassette` — самый простой путь)

1. `/cassette` — список библиотеки; у каждой плёнки кнопка **🎞** → «Редактор плёнки».
2. **Контекст плёнки** под шапкой редактора: 🟢 если назначена «следующей», ▶ если
   играется (месяц совпадает с текущим) — «сегодня день N · дорога X» (честное
   решение движка, fail-open в main).
3. **Прочитать / скачать:** «Скачать месяц (.yaml)» — весь месяц YAML-документом;
   «Скачать день» → сетка дней (сверху кнопки дорог: main и перемотки) → кнопка с
   номером N — фрагмент дня одним YAML-файлом; «Прочитать день» → номер N — кадр
   текстом в чат.
4. **Вернуть месяц/день:** «📤 Вернуть …» — бот встаёт в режим «жду документ»; пришли
   скачанный `.yaml` (исправленный) — отчёт «✅ Сценарий принят: …» или «❌ …» с полями
   ошибок. Дорогу дня бот узнаёт из метки фрагмента `# дорога: …`: день 20 на
   перемотке morning встанет в `switch`, а не в main. Отмену — «⏹ Отменить загрузку».
5. **Проверить без записи:** «🔎 Проверить месяц/день» — валидация файла (сумма дней,
   форма, контракт), файл кассеты не трогается; отчёт «✅ … Проверено — файл не
   изменён». Удобно перед штатной правкой, чтобы поймать опечатку YAML.
6. **Новая кассета:** «➕ Новый месяц» — пришли сценарий нового месяца документом
   (образец возьми «Скачать месяц» любой плёнки). Имя выводится из `cassette_id`
   и месяца (`мел-2026-02.json`); существующие плёнки перезаписывать нельзя.
7. **Undo:** каждая запись правки делает бэкап `*.json.bak`; восстановить предыдущий
   вариант — «🗄 Вернуть бэкап» (кнопка в сцене и в отчёте правки). Бэкап перед
   копией валидируется, битый не трогает рабочую кассету.
8. Намерение «жду документ» живёт в `watcher_state` (`STORY_CASSETTE_EDIT_KEY`),
   держится до приёма документа или отмены — зависнуть нельзя.

Документы читаются как текст (UTF-8, с BOM терпимо). После записи проигрыватель
`bay.py` перечитывает файл по mtime на ближайшем рендере.

### Из терминала (CLI — тот же редактор, без Telegram)

```
.\.venv\Scripts\python scripts\cassette_tool.py dump app\story\cassettes\imeniny-chasov.json
                              # месяц целиком: пишет imeniny-chasov.yaml рядом с json (или -o сценарий.yaml)
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 14 --road morning
.\.venv\Scripts\python scripts\cassette_tool.py dump ... --day 12 -o edits/day12.yaml
                              # фрагмент дня (с меткой # дорога: …)
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits/day12.yaml --check
                              # дорога и день читаются из фрагмента, флаги не нужны
.\.venv\Scripts\python scripts\cassette_tool.py patch  ... edits/day12.yaml --day 12 --road morning
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\imeniny-chasov.yaml --check
.\.venv\Scripts\python scripts\cassette_tool.py compile edits\imeniny-chasov.yaml   # на место
```

`--check` — валидация без записи. `--day`/`--road` — явный override: по умолчанию
день и дорога читаются из самого фрагмента (day_index и `# дорога: …`); `--day` ещё
и сверяет заявленное с фрагментом (страховка от ручной правки).

### Что можно и что нельзя

- Можно: правки глав/текста/вариантов внутри месяца, дорог перемотки (фрагмент
  с `--road morning`), титула, logline; эха `prev` и дневника `diary` (видны в
  «Прочитать день» как строки «(эхо…)»/«(дневник стаи)»); новую кассету («➕ Новый
  месяц» — имя из cassette_id+месяца); откат правки («🗄 Вернуть бэкап»). Ограничение
  «3 карты, position 0/1/2, день = календарю» — то же, что у автора (§1):
  недееспособную правку не примет ни бот, ни CLI.
- Нельзя из бота/CLI: переименовать существующий файл, менять число дней месяца,
  дистрибуцию, законы дня — это за движком (жёсткая рамка в начале документа).
- Тесты вокруг редактора: `tests/test_cassette_editor.py` (ядро + панель),
  `tests/test_cassette_tool.py` (CLI round-trip).
